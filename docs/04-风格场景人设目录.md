> 本章所有文本均为**从 APK 中提取的原文**，可直接复制使用。

## 4.1 场景（`Scene`）

```kotlin
enum class Scene(val label: String) {
    ALL("全部"),
    WORKPLACE("职场"),
    LOVE("恋爱"),
    SOCIAL("社交"),
    GENERAL("通用"),
}
```

`StyleCatalog.ofScene(scene)` 按场景筛选；`Scene.ALL` 返回全部风格。

## 4.2 风格（`StylePreset`）

```kotlin
data class StylePreset(
    val id: String,
    val name: String,
    val emoji: String,
    val scene: Scene,
    val tagline: String,        // 卡片副标题
    val systemPrompt: String,   // 注入 system 的角色设定
    val temperature: Float = 0.8f,   // 注意：默认值 0.8，不是 0.7
    val hints: List<String> = emptyList(),  // 离线话术，{他} 会被替换成人设名
)
```

**默认选中**（`StyleCatalog.defaultSelection`）：`["high_eq", "pro", "funny"]`
**UI 上限**：最多同时选 **5** 种风格（超出提示：「一次最多横向对比 5 种风格，先去掉一个吧」）

## 4.3 表达强度（`strength`，1–5）

| 值 | 注入 system 的文本 |
| --- | --- |
| 1 | 表达要非常含蓄委婉，多用缓冲词，把态度藏在客气话里，绝不直接下结论。 |
| 2 | 表达偏含蓄，先照顾对方感受，再轻描淡写地带出自己的态度。 |
| 3 | 表达自然平衡，既说清态度也不让对方难堪。**（默认）** |
| 4 | 表达偏直接，先给结论再补一句缓冲，不含糊、不绕弯。 |
| 5 | 表达非常直接，开门见山给出明确态度，不解释、不铺垫、不留余地。 |

> UI 上对应文案是「偏含蓄 / 偏直接」「很含蓄 / 很直接」等，强度值越界时回退到 3。

## 4.4 说话对象（`Persona`）

用户自建，字段：`id / name / relation / tone / taboo`。

在「设置」页和「对象」页出现的提示文案（原文）：

- 称呼示例：`例如：老板`
- 关系示例：`例如：直属上级`
- 语气示例：`例如：简洁、尊重、不要用感叹号`
- 禁忌示例：`例如：不要太软，我要保住立场`
- 补充要求示例：`例如：这个需求今晚能给我吗？`

注入 system 的形式：

```
【说话对象】对方是你的{relation}，称呼「{name}」。语气要求：{tone}。绝对不要出现：{taboo}。
```

## 4.5 离线模板引擎（`LocalTemplateEngine`）

未配置 API Key，或 AI 调用失败时使用。

### 意图识别（`Intent`）

7 种意图，按**顺序**匹配，命中即返回；全不命中则为 `CHAT`：

| 顺序 | Intent | 触发关键词 |
| --- | --- | --- |
| 1 | `APOLOGY` | 对不起、抱歉、我错了、不好意思 |
| 2 | `BLAME` | 你怎么、为什么没、又这样、说好的、你明明 |
| 3 | `INVITE` | 一起、要不要、来吗、参加、有空吗、约吗、约个、约一下、约饭、约会、约你 |
| 4 | `FLIRT` | 想你、喜欢你、在干嘛、晚安、想见你、心动 |
| 5 | `REQUEST` | 帮我、帮忙、能不能、可以吗、麻烦你、请你、借我、加个班、支持一下 |
| 6 | `QUESTION` | `?`、`？`、怎么、为什么、多少、什么、是不是 |
| — | `CHAT` | 兜底 |

**「约」字误报处理**：`INVITE` 里以「约」开头的关键词会额外检查前一个字符，若构成 `大约/预约/节约/制约/签约/合约/条约/违约/盟约/履约/续约/毁约/邀约` 之一，则不算命中。

### 生成规则

```kotlin
fun generate(request: ReplyRequest, seed: Int): List<Reply> {
    val intent = Intent.of(request.incoming)
    val speaker = request.persona?.name?.takeIf { it.isNotBlank() } ?: "你"
    return request.styles.map { style ->
        val hints = style.hints.ifEmpty { listOf("收到，我想想怎么回。") }
        val idx = ((seed + intent.ordinal) % hints.size + hints.size) % hints.size
        Reply(
            styleId = style.id, styleName = style.name, emoji = style.emoji,
            text = hints[idx].replace("{他}", speaker),
            source = ReplySource.LOCAL,
        )
    }
}
```

要点：

- 每种风格取 `hints` 里的一条，**索引由 `seed + intent.ordinal` 决定** —— 所以同一个输入点「换一批」会轮换到不同话术。
- `{他}` 占位符替换为当前人设的 `name`，没有则用 `你`。
- 任何风格若 `hints` 为空（理论上不会，12 种都有 3 条），兜底为「收到，我想想怎么回。」。

## 4.6 每日话术（`DailyTipCatalog`）

12 条，按「一年中的第几天」取模轮换（`forDayOfYear` / `today(now)`）。

| 标题 | 正文 |
| --- | --- |
| 拒绝的三段式 | 先肯定对方，再说明自己的限制，最后给一个替代方案。比直接说「不行」更容易被接受。 |
| 催进度别用「你怎么还没」 | 换成「我这边卡在这一步，需要你周三前给个结果」，把指责变成协作，对方更容易动。 |
| 被夸的时候别急着否认 | 说「谢谢，这话我收下了」就够了。急着谦虚，反而让夸奖的人尴尬。 |
| 道歉只讲两件事 | 承认具体做了什么，再说怎么补。不要加「但是」，那会毁掉前半句。 |
| 拒绝邀约的标准句式 | 「谢谢想到我，这次时间冲突了，下次有机会我第一个答应。」不解释、不找理由。 |
| 要资源前先给结论 | 先说「我需要 X，因为 Y，最晚 Z 前要」，再补背景。上级没耐心听铺垫。 |
| 冷场时接话的技巧 | 别问「你怎么看」，改问「如果是你会选哪个」。给选项比给开放题更好接。 |
| 被阴阳时的体面回应 | 「我记下了，咱们还是看结果说话。」不接情绪，只接事实。 |
| 道歉要趁早 | 拖延不会让事情变小，只会让对方把「你不重视」也一起算进去。 |
| 别在气头上发消息 | 先写好，存草稿，十分钟后再看一遍。想删掉的那句，通常就是该删的。 |
| 提需求带上方案 | 「这里有问题，我建议这样改，你看行不行？」带方案的人很少被拒绝。 |
| 拒绝闲聊式加班 | 「今天我有安排，明早九点前给你。」给明确时间，比「尽量」更有边界感。 |

另有「断签提醒」固定文案：

- 标题：`今天还没让嘴替开工`
- 正文：`有句话不知道怎么回？粘过来，三秒给你几个版本。`
