## 5.2 生成流程（`MainViewModel.startGeneration`）

点击「生成」/「换一批」时按**固定顺序**校验，任一不过就只弹提示、不发起请求：

| 步骤 | 检查 | 不过时的提示 |
| --- | --- | --- |
| 1 | `SafetyFilter.validateInput(input)` | 见 5.3 |
| 2 | `StyleCatalog.selectedInScene(选中ids, 场景)` 非空 | `至少选一种风格` |
| 3 | `SettingsStore.checkQuota()` | `今天的免费次数用完了，明天再来，或升级会员解锁无限次。` |
| 4 | 通过 → `seed = repository.newSeed()`，组装 `ReplyRequest`，取消上一次未完成的生成任务，启动新协程 | — |

### 生成协程的完整行为

```kotlin
viewModelScope.launch {
    repository.clearAiError()
    _ui.update { it.copy(
        genState = GenState.Loading(done = 0, total = styles.size),
        showResult = true, message = null, aiError = null,
    ) }

    val collected = mutableListOf<Outcome>()
    val errors    = mutableListOf<String>()
    val lock      = Mutex()

    val jobs = styles.map { style ->
        launch(Dispatchers.IO) {                       // ← 每种风格一个协程，并发
            val result = runCatching {
                repository.generateOutcome(request, style, seed, bypassCache)
            }
            val outcome = result.getOrElse { e ->
                if (e is CancellationException) throw e   // 取消要透传，不能吞
                Outcome(
                    reply = Reply(style.id, style.name, style.emoji,
                                  "这次没生成出来，点「换一批」再试试。",
                                  ReplySource.LOCAL),
                    error = e.message,
                    fromCache = false,
                )
            }
            lock.withLock {
                collected.add(outcome)
                outcome.error?.let { errors.add(it) }
                _ui.update { it.copy(
                    genState = GenState.Loading(collected.size, styles.size),
                ) }
            }
        }
    }
    jobs.joinAll()

    // 按风格顺序对齐结果（并发完成顺序不定）
    val replies = styles.mapNotNull { s ->
        collected.firstOrNull { it.reply.styleId == s.id }?.reply
    }

    // 计费判定
    val hasAiReply  = replies.any { it.source == ReplySource.AI }
    val allFromCache = collected.isNotEmpty() && collected.all { it.fromCache }
    val aiFailed = aiReadyAtStart && !hasAiReply
    if (!allFromCache && !aiFailed) settings.consumeQuota()

    _ui.update { it.copy(
        genState = GenState.Done(replies),
        aiError  = errors.distinct().firstOrNull(),
    ) }
}
```

几个值得注意的点：

1. **并发不是串行** —— 每种风格一个 `Dispatchers.IO` 协程，用 `Mutex` 保护共享列表，最后 `joinAll()`。
2. **结果按风格顺序重排** —— 因为并发完成顺序不定，用 `styleId` 对齐，保证 UI 上卡片顺序与选择顺序一致。
3. **单风格失败不影响整体** —— 该风格会拿到一条占位回复 `这次没生成出来，点「换一批」再试试。`（`ReplySource.LOCAL`），其余风格正常显示。
4. **计费时机在全部完成之后，而不是发起时**：
   - 全部命中缓存 → **不扣**
   - AI 已配置但一条 AI 结果都没拿到（全部走了离线兜底）→ **不扣**（不给失败的调用收费）
   - 其他情况 → 扣 1 次
5. **`GenState.Failed` 在这条路径上不会被设置** —— 无论成功失败最终都落到 `Done`。单条错误信息通过 `aiError` 字段展示。
6. **错误消息去重**：`errors.distinct().firstOrNull()`，多种风格报同样的错时只显示一条。

**注意**：第 2 步用的是 `selectedInScene`，也就是**只统计当前场景下可见的风格**。切到「职场」场景时，之前选的「撒娇」不计入，可能出现「明明选了风格却提示至少选一种」。

### 输入长度限制（三层，别搞混）

| 限制 | 值 | 行为 |
| --- | --- | --- |
| `SafetyFilter.MAX_INPUT_LENGTH` | 600 | **软提示**：`内容有点长，截取最关键的 600 字以内效果更好。` 直接拦截 |
| `SafetyFilter.HARD_INPUT_LIMIT` | 6000 | **硬截断**：输入框内容超过 6000 字直接 `take(6000)`，同时 `inputTruncated = true` |
| 补充要求 `extraHint` | 60 | 直接 `take(60)` 截断 |

### 表达强度

`onStrengthChange` 用 `coerceIn(value, 1, 5)`，越界自动夹到 1–5。

### 风格多选上限

`toggleStyle` 中：**已选数量 < 5** 才允许新增；达到 5 时提示

> `一次最多横向对比 5 种风格，先去掉一个吧`

取消选择无限制。

## 5.3 安全过滤（`SafetyFilter`）

三层机制：

### ① 输入黑名单（24 条，命中即拦截）

提示：`这类内容嘴替帮不上忙，换个场景试试。`

24 条全部是**具体短语**（不是关键词），涉毒、涉枪、涉赌、诈骗、伪造，以及开盒/人肉/网暴的具体问法：

```
怎么开盒 / 如何开盒 / 帮我开盒 / 开盒教程 / 开盒方法
人肉搜索教程 / 帮我人肉 / 人肉搜索方法
怎么网暴 / 帮我网暴 / 网暴教程
诈骗话术 / 骗保 / 开票冲账 / 伪造证件 / 赌博网站
辱骂模板 / 人身攻击模板
炸药 / 枪支 / 毒品 / 冰毒 / 洗钱 / 裸聊
```

> ⚠️ **覆盖缺口（原实现如此，不是重写引入的）**：列表里**没有裸的「开盒」**，也**没有裸的「人肉搜索」**。所以单说「开盒」「人肉搜索」不会被拦，只有带上具体问法（如「怎么开盒」）才拦。输出侧的黑名单反而更宽 —— 有裸的「开盒」和「人肉」。

### ② 输出黑名单（8 条，命中则丢弃该条结果）

提示：`内容未通过安全校验`，并回退到离线模板。

```
炸药 / 枪支 / 毒品 / 洗钱 / 诈骗 / 裸聊 / 开盒 / 人肉
```

### ③ 否定前缀白名单（16 条）

命中黑名单词后，**回看该词前 3 个字符**，如果以以下词结尾，则**不算命中**：

```
不是 / 不算 / 没有 / 不会 / 并非 / 别 / 无需 / 不用 /
拒绝 / 防 / 反 / 警惕 / 小心 / 避免 / 切勿 / 不要
```

举例（均已通过单元测试验证）：

| 输入 | 结果 | 原因 |
| --- | --- | --- |
| `防诈骗话术` | ✅ 放行 | 「防」紧贴在「诈骗话术」前 |
| `拒绝帮我开盒` | ✅ 放行 | 「拒绝」紧贴 |
| `不要嗯嗯嗯怎么开盒` | 🚫 拦截 | 中间隔了 3 个字符，窗口取到「嗯嗯嗯」 |
| `诈骗话术，请注意防范` | 🚫 拦截 | 否定词出现在命中词**之后**，无效 |
| `不要怎么开盒，如何开盒` | 🚫 拦截 | 第一处被豁免，第二处没有 |

> **注意：回看窗口只有 3 个字符，且必须紧贴。** 所以「如何防范诈骗话术」这种说法**会被误杀** —— 窗口取到的是「何防范」，不是「防」。原实现并没有真正解决「正常讨论被误杀」的问题。

> 实现细节：`hitsRiskyWord()` 会遍历文本中该词的**所有出现位置**，只有**全部**出现都带安全前缀才放行。

## 5.4 配额（`SettingsStore`）

| 规则 | 值 |
| --- | --- |
| 免费额度 | `FREE_DAILY_QUOTA = 10` 次/天 |
| 重置时机 | 每次读取时对比 `quota_date` 与今天，不同则 `quota_used = 0` |
| 计数时机 | `consumeQuota()`，同时写入 `last_active_date = today` |
| 会员 | `isPro = true` 时 `remaining = Int.MAX_VALUE`，`exhausted` 恒为 `false` |

**重要**：`isPro` 只是本地 SharedPreferences 开关（设置页有「模拟会员状态」开关），**项目里没有任何支付/服务端校验逻辑**。源码注释级线索：

> `接入支付后由订单回调控制，MVP`（设置页文案片段）

| --- | --- |

## 5.7 每日推送（WorkManager）

| 项 | 值 |
| --- | --- |
| 唯一任务名 | `mouthpiece_daily_tip`、`mouthpiece_streak` |
| 周期 | 24 小时 |
| 首次延迟 | 计算到下一个目标整点的毫秒数（`PushTime.millisUntil`） |
| 话术推送小时 | 用户在 8 / 9 / 12 / 20 中选，默认 9 |
| 断签提醒小时 | 固定 21 点（`STREAK_NOTIFY_HOUR = 21`） |
| 通知渠道 id | `mouthpiece_daily` |
| 渠道名称 | `每日话术` |
| 渠道重要性 | `IMPORTANCE_DEFAULT`（3） |
| 通知 id | 话术 = 1001，断签 = 1002 |
| 小图标 | `R.drawable.ic_notification` |

**断签逻辑**（`sendStreakIfNeeded`）：只有 `last_active_date != today` 才发 —— 也就是「今天一次都没用过」才提醒。

**调度策略**（`PushScheduler.sync`）：

- `enabled == false` → 取消两个任务
- `force == true` → `CANCEL_AND_REENQUEUE`（重新排期）
- `force == false` → `KEEP`（已有任务保持不动）

调用点：`MouthpieceApp.onCreate()`（force=false）、`ServiceLocator.syncPushSchedule()`（设置变更时）。

推送说明文案（原文）：`约在所选时间推送；受系统省电策略影响可能延后几十分钟，属正常现象。`

## 5.8 外部文本接入

`MainActivity` 注册了三个 intent-filter：

| Action | 触发方式 | 取文本字段 |
| --- | --- | --- |
| `MAIN` / `LAUNCHER` | 桌面图标 | — |
| `SEND`（`text/plain`） | 系统分享菜单 | `Intent.EXTRA_TEXT` |
| `PROCESS_TEXT`（`text/plain`） | 选中文本后的浮动菜单 | `Intent.EXTRA_PROCESS_TEXT` |

处理逻辑：`trim()` 后若非空，通过 `ServiceLocator.emitSharedText()` 投进 `Channel`，`MainViewModel.onSharedText()` 消费并写入输入框。

`launchMode = "singleTask"` + `onNewIntent()` 保证从分享进入时复用同一个 Activity 实例。
