## 2.1 数据模型总览

```
AppSettings ──┐
              ├──► ReplyRequest ──► PromptBuilder ──► AiGateway ──► Reply
Persona ──────┘         │                                          │
                        └──► StylePreset ──► LocalTemplateEngine ──┘
```

### AppSettings（设置）

```kotlin
data class AppSettings(
    val baseUrl: String = DEFAULT_BASE_URL,   // "https://api.openai.com/v1"
    val apiKey: String = "",                  // 默认空 —— 必须用户自己填
    val model: String = DEFAULT_MODEL,        // "gpt-4o-mini"
    val watermark: Boolean = true,            // 分享卡片带水印（默认开）
    val incognito: Boolean = false,           // 无痕模式
    val personaId: String? = null,            // 当前选中的说话对象
    val notifyEnabled: Boolean = false,
    val notifyHour: Int = 9,
) {
    val aiReady: Boolean get() = apiKey.isNotBlank()

    companion object {
        const val DEFAULT_BASE_URL = "https://api.openai.com/v1"
        const val DEFAULT_MODEL = "gpt-4o-mini"
        const val FREE_DAILY_QUOTA = 10
        const val DEFAULT_NOTIFY_HOUR = 9
        const val STREAK_NOTIFY_HOUR = 21
        val NOTIFY_HOURS = listOf(8, 9, 12, 20)
    }
}
```

### QuotaState（配额）

```kotlin
data class QuotaState(val used: Int, val limit: Int, val isPro: Boolean) {
    val remaining: Int get() = if (isPro) Int.MAX_VALUE else maxOf(limit - used, 0)
    val exhausted: Boolean get() = !isPro && used >= limit
}
```

## 2.2 持久化方案（三种，别搞混）

原项目**没有使用 Room 存业务数据**。APK 里的 `androidx.room.*` 类全部来自 WorkManager 的内部依赖，不是 App 自己建的库。

| 数据 | 存储位置 | 方式 |
| --- | --- | --- |
| 设置 + 配额 | SharedPreferences **`mouthpiece_settings`** | 逐字段 put/get |
| 说话对象档案 | SharedPreferences **`mouthpiece_personas`** | 单键 `personas_json`，存 JSON 数组 |
| 历史记录 | 文件 `filesDir/history.json` | JSON 数组 + 备份 + 原子写 |

### SharedPreferences：`mouthpiece_settings`

`SettingsStore` 的键（全部实测自 APK）：

| 键 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `base_url` | String | `https://api.openai.com/v1` | 接口地址 |
| `api_key` | String | `""` | API Key |
| `model` | String | `gpt-4o-mini` | 模型名 |
| `watermark` | Boolean | `true` | 分享卡片带水印 |
| `incognito` | Boolean | `false` | 无痕模式 |
| `persona_id` | String? | `null` | 当前说话对象 |
| `notify_enabled` | Boolean | `false` | 每日推送开关 |
| `notify_hour` | Int | `9` | 推送小时（可选 8/9/12/20） |
| `is_pro` | Boolean | `false` | 会员开关（本地模拟） |
| `quota_date` | String? | `null` | 配额对应的日期（`yyyy-MM-dd`） |
| `quota_used` | Int | `0` | 当天已用次数 |
| `last_active_date` | String? | `null` | 最近一次使用日期（用于断签提醒） |

**跨天重置逻辑**：读取配额时若 `quota_date != today`，则写入 `quota_date = today` 并把 `quota_used` 归零。

**计数逻辑**：`consumeQuota()` 时 `quota_used += 1`，同时把 `last_active_date = today`。

### SharedPreferences：`mouthpiece_personas`

单键 `personas_json`，值为 `Persona` 数组的 JSON 文本，用 `org.json` 手工编解码。读取失败时回退为空列表。

### 文件：`history.json`

`HistoryStore` 的实现明显是「怕丢数据」的思路：

```kotlin
private val file   = File(context.filesDir, "history.json")
private val backup = File(context.filesDir, "history.json.bak")

companion object {
    const val MAX_ITEMS = 500
    const val WRITE_DEBOUNCE_MS = 500L
    const val FLUSH_LOCK_TIMEOUT_MS = 50L
}
```

行为要点：

1. **启动读取**：读 `history.json`；解析失败则 `recoverFromBackup()` 读 `history.json.bak`。
2. **原子写**：写入时先写 `history.json.tmp`，再把当前 `history.json` 拷成 `.bak`，最后改名替换。
3. **防抖**：写请求先进 `pendingWrite`，由 IO 协程 `delay(500)` 合并后统一落盘，用 `ReentrantLock` 保护。
4. **主动刷盘**：`flush()` 立即落盘 —— 由 `MouthpieceApp.onTrimMemory(TRIM_MEMORY_UI_HIDDEN)` 和 `ServiceLocator.flushHistory()` 调用。
5. **上限**：`MAX_ITEMS = 500`，超出后裁剪。
6. **ID 生成**：`AtomicLong`，初值为已加载条目中的最大 `id`，保证单调递增。
7. **无痕模式**：开启后 `HistoryStore.add()` 不会被调用，因此不落盘。

## 2.3 JSON 编解码

`HistoryCodec` 用 **`org.json`**（`JSONObject` / `JSONArray`），**不是 kotlinx.serialization**。

> 说明：APK 里确实有 `kotlinx/serialization/*` 类，但只有 `core` / `internal` / `descriptors` / `modules` / `encoding`，**没有 `json` 包** —— 这是 `androidx.savedstate 1.3.0` 的传递依赖，App 自身没有用。

`HistoryCodec` 提供四个方法：

| 方法 | 说明 |
| --- | --- |
| `encode(items): String` | 列表 → JSON 数组文本 |
| `decode(raw): List<HistoryItem>` | 容错解码，失败返回空列表 |
| `decodeOrNull(raw): List<HistoryItem>?` | 失败返回 `null` |
| `readOne(array, index): HistoryItem` | 单条解析（字段缺失时给默认值） |

解码后会按 `createdAt` **降序排序**。

## 2.4 内存态缓存

`ReplyRepository` 持有一个内存缓存，避免重复请求同一个提示词：

```kotlin
const val REPLY_CACHE_MAX = 200   // ReplyRepositoryKt

private val cache = Collections.synchronizedMap(
    object : LinkedHashMap<String, Reply>(REPLY_CACHE_MAX, 0.75f, true) { ... }
)
```

**缓存键**（`cacheKey()`）由 7 段拼接，每段是 `长度:值|` 的格式：

```
baseUrl | model | styleId | strength | personaId(或空) | extraHint | incoming
```

也就是说：**换模型、换风格、换强度、换对象、改补充要求、改原话，任一变化都会 miss**。用户点「换一批」时传 `bypassCache = true` 强制绕过。
