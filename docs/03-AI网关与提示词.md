# 03 · AI 网关与提示词

## 3.1 接口定义

```kotlin
interface AiGateway {
    suspend fun complete(system: String, user: String, temperature: Float): String
}
```

只有一个方法，只做「给 system + user，返回一段文本」。业务语义（风格、强度、对象）全部通过提示词注入，网关本身不感知。

实现类只有一个：`OpenAiCompatGateway`。

```kotlin
class OpenAiCompatGateway(
    private val settingsProvider: () -> AppSettings,
) : AiGateway
```

构造参数是 `() -> AppSettings` 而不是 `AppSettings` —— 这样设置改了之后无需重建网关。

## 3.2 端点拼接

```kotlin
fun chatCompletionsEndpoint(baseUrl: String): String {
    val trimmed = baseUrl.trim().trimEnd('/')
    if (trimmed.isEmpty()) return ""
    return if (trimmed.endsWith("/chat/completions")) trimmed
           else "$trimmed/chat/completions"
}
```

- 用户填 `https://api.openai.com/v1` → `https://api.openai.com/v1/chat/completions`
- 用户直接填完整地址 → 原样使用
- 空字符串 → `""`（调用前会先被 `未配置接口地址` 拦下）

## 3.3 请求构造

### 请求头

```http
POST <endpoint> HTTP/1.1
Content-Type: application/json; charset=utf-8
Authorization: Bearer <apiKey>
```

### 超时

| 项 | 值 | 来源 |
| --- | --- | --- |
| `connectTimeout` | 8 000 ms | 硬编码 |
| `readTimeout` | 25 000 ms | `AiTimeouts.READ_MS` |
| 整体上限 | 40 000 ms | `AiTimeouts.TOTAL_MS` |

### 请求体

```json
{
  "model": "<AppSettings.model>",
  "temperature": <StylePreset.temperature>,
  "max_tokens": 2048,
  "messages": [
    { "role": "system", "content": "<PromptBuilder.system(request)>" },
    { "role": "user",   "content": "<PromptBuilder.user(request)>" }
  ],
  "reasoning_effort": "max"
}
```

常量：

```kotlin
const val MAX_TOKENS = 2048
const val MAX_TOKENS_RETRY = 4096
const val REASONING_EFFORT = "max"
```

### 调用前的守卫

按顺序检查，任一为空就抛 `IOException`：

| 条件 | 异常消息 |
| --- | --- |
| `apiKey.isBlank()` | `未配置 API Key` |
| `baseUrl.isBlank()` | `未配置接口地址` |
| `model.isBlank()` | `未配置模型名` |

## 3.4 重试与降级策略

> 下面这段控制流由恢复状态机恢复（Kotlin 的 `suspend` 被展开成 `switch(label)`），**分支顺序可能与原始代码略有差异，但语义一致**。

```
第 1 次请求
  body: max_tokens=2048, reasoning_effort="max"
       │
       ├─ HTTP 400 或 响应体含 "reasoning" / "effort"
       │     └─► 判定为「不支持 reasoning_effort 参数」
       │          第 2 次请求：去掉 reasoning_effort，max_tokens=2048
       │
       └─ 其他
             └─► 直接解析
                    │
                    └─ content 为空 且 finish_reason == "length"
                          └─► 第 3 次请求：max_tokens=4096（不再带 reasoning_effort）
```

设计意图很清楚：**兼容面尽量宽**。有些中转服务/国产模型不支持 `reasoning_effort`，有些模型输出被 `max_tokens` 截断 —— 两种情况各留一次补救机会。

### 响应解析

```kotlin
choices[0].message.content      // 正文
choices[0].finish_reason        // 用于判断是否被截断
```

逐层校验，任何一层不对就抛 `IOException`：

| 情况 | 异常消息 |
| --- | --- |
| 整体不是合法 JSON | `服务端返回的不是合法 JSON` |
| 缺 `choices` | `服务端返回缺少 choices 字段` |
| `choices` 为空数组 | `模型没有返回任何候选结果` |
| `choices[0]` 不是对象 | `模型返回结构异常` |
| 缺 `message` | `模型返回结构异常` |
| `content` 为空 | `模型返回空内容` |

### 返回前的清洗

```kotlin
fun clean(text: String): String =
    text.trim()
        .removePrefix("回复：").removePrefix("回复:")
        .trim()
        .trim('"', '“', '”')
        .trim()
```

即：去掉首尾空白 → 去掉模型爱加的「回复：」前缀 → 再去掉包裹的引号。

### HTTP 错误翻译

| 状态码 | 用户可见文案 |
| --- | --- |
| 400 | `HTTP 400：请求被拒绝，通常是模型名或参数不被支持` |
| 401 / 403 | `HTTP 401/403：API Key 无效或没有权限` |
| 404 | `HTTP 404：接口地址不存在，请检查是否填到 /v1 为止` |
| 408 | `HTTP 408：服务端等待超时` |
| 413 | `HTTP 413：请求体过大` |
| 429 | `HTTP 429：请求过于频繁或余额/额度不足` |
| 5xx | `HTTP 5xx：服务端暂时不可用，请稍后重试` |
| 其他 | `HTTP <code>` |

### 网络异常翻译

| 异常 | 用户可见文案 |
| --- | --- |
| `SocketTimeoutException` | `服务端响应超时（单次请求 25 秒），请稍后重试` |
| `UnknownHostException` | `无法解析接口地址，请检查网络与「设置 → AI 服务」里的地址` |
| `ConnectException` | `无法连接接口地址，请检查地址是否正确、网络是否可用` |
| 其他 | 原样抛出 |

## 3.5 提示词组装（`PromptBuilder`）

### system

```
{StylePreset.systemPrompt}

【表达强度】{strengthRules[strength]}

【说话对象】对方是你的{relation}，称呼「{name}」。语气要求：{tone}。绝对不要出现：{taboo}。

【输出要求】只输出一条可以直接发送的回复正文，不要任何解释、标题、序号或引号；口语化、可读性强，控制在 80 字以内；不要提及自己是 AI，也不要提及「嘴替」。
```

其中 `strengthRules` 为固定 5 档（实测原文）：

| strength | 规则文本 |
| --- | --- |
| 1 | 表达要非常含蓄委婉，多用缓冲词，把态度藏在客气话里，绝不直接下结论。 |
| 2 | 表达偏含蓄，先照顾对方感受，再轻描淡写地带出自己的态度。 |
| 3 | 表达自然平衡，既说清态度也不让对方难堪。（**默认值**） |
| 4 | 表达偏直接，先给结论再补一句缓冲，不含糊、不绕弯。 |
| 5 | 表达非常直接，开门见山给出明确态度，不解释、不铺垫、不留余地。 |

【说话对象】整段只有在 `persona != null` 时才拼接；`relation` 为空时用 `沟通对象` 兜底；`tone` / `taboo` 为空则跳过对应句子。

### user

```
对方对我说：
{incoming}

补充要求：{extraHint}

请给出你的回复。
```

`extraHint` 为空时省略「补充要求」那段。

### 关键设计点

- **只生成一条**：prompt 里明确要求「只输出一条…不要任何解释」。所以**每种风格一次只出一条回复**，UI 上的「多个版本」是靠**多选风格**实现的（最多 5 种 → 最多 5 条）。
- **80 字上限**写在提示词里，不是硬截断。
- **不暴露身份**：明确禁止提 AI、禁止提「嘴替」。
- `temperature` 由风格决定（0.0 – 1.0，见 `docs/04`），不随强度变化。

## 3.6 完整调用链（`ReplyRepository.generateOutcome`）

```
generateOutcome(request, style, seed, bypassCache)
  │
  ├─ single = request.copy(styles = listOf(style))     // 拆成单风格请求
  ├─ config = settingsProvider()
  │
  ├─ if (!config.aiReady)                              // 没配 Key
  │     └─► 返回 Outcome(local.generate(single, seed).first(), error = null)
  │
  ├─ key = cacheKey(request, style, config)
  ├─ if (!bypassCache && cache[key] != null)           // 命中缓存
  │     └─► 返回 Outcome(cached, error = null, fromCache = true)
  │
  ├─ try:
  │    system = PromptBuilder.system(single)
  │    user   = PromptBuilder.user(single)
  │    text   = ai.complete(system, user, style.temperature)
  │    clean  = clean(text)
  │    if (!SafetyFilter.isOutputSafe(clean))
  │         └─► throw IllegalStateException("内容未通过安全校验")
  │    reply = Reply(style.id, style.name, style.emoji, clean, AI)
  │    cache[key] = reply
  │    └─► 返回 Outcome(reply, error = null)
  │
  └─ catch:
       _lastAiError.value = e.message ?: e::class.simpleName
       └─► 返回 Outcome(local.generate(single, seed).first(), error = <错误消息>)
```

要点：

1. **永远有兜底**：任何异常都会回退到离线模板，用户不会看到空白结果，只会看到「这次用的是离线模板」的提示。
2. **错误通过 `lastAiError: StateFlow<String?>` 广播**，UI 消费后用 `clearAiError()` 清掉。
3. **缓存写入在安全校验之后**，被拦下的内容不会进缓存。
4. **多风格是并发调用**：每种风格一次 `complete` 请求，由 `MainViewModel` 并发发起（见 `docs/05` §5.2），不是一次请求要 N 条。
