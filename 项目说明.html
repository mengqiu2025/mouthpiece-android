二、这个 App 是什么

「不知道怎么回消息？粘过来，三秒给你几个版本。」

粘贴对方发来的话 → 选场景 + 风格 + 表达强度 → 调用用户自带的 OpenAI 兼容大模型 → 生成多条可直接发送的回复 → 复制 / 收藏 / 生成分享卡片。

核心业务规则

接入方式用户自带 Key。不内置任何 API Key；未配置时全部走内置离线模板，功能可用但不够贴合语境
免费额度每天 10 次，跨天自动重置。会员（is_pro）为本地开关，无任何支付逻辑
安全过滤输入 24 条黑名单 + 输出 8 条黑名单，带 16 条「否定前缀白名单」（「不要开盒」不会被误杀）
风格12 种，跨 4 个场景，最多同时选 5 种并发生成
离线兜底7 类意图识别 + 每风格 3 条话术，任何 AI 异常都会回退，永不空白
每日推送WorkManager 每 24h 推一条沟通话术；另有「断签提醒」（当天一次都没用过才发）
分享入口支持系统分享（ACTION_SEND）与选中文本菜单（ACTION_PROCESS_TEXT）

最重要的限制：这份源码不能直接编译 原项目是 Kotlin + Compose，恢复出的源码是 Java。编译器把 Kotlin 重塑成了 Java 能表达的形态：suspend 变成 switch(label) 状态机、@Composable 变成带 Composer 参数的静态方法、data class 变成手写的 copy/equals/hashCode。 逻辑是完整可读的，但形态必须重写。
一个容易读错的陷阱：Kotlin 默认参数位掩码 恢复出的代码里会出现 new StylePreset(..., 0.0f, listOf(...), 64, null)。那个 0.0f 是假的，64 才是关键 —— 二进制 1000000 表示第 6 个参数（temperature）用了默认值 0.8。本项目 4 个风格踩了这个坑，文档里已修正。

十一、重新发布前必须知道的两件事

① 签名密钥无法恢复 APK 里只有公钥证书（CN=Mouthpiece Test 自签名测试证书），私钥不在包内，不可恢复。重新发布的 APK 与原 App 签名不同，老用户无法覆盖安装。
② 但这不是问题 证书是自签名测试证书、AppInfo.CHANNEL = "内测版"、debug 包带 android:debuggable="true" —— 说明 v0.1.4 是内测阶段产物，从未正式上架。重启时可以放心重新设计包名与签名策略。

另外几处「半成品」，重启时值得先决策

  • 模型调用方式：用户自带 Key 直连会让 Key 暴露在客户端，且无法计费。做商业产品需改为自有服务端代理。
  • 会员与支付：只有本地 is_pro 开关，文案已写（「接入支付后由订单回调控制，MVP」），实现为零。
  • 安全过滤：24 + 8 条关键词硬编码，会持续过期。建议改为可远程更新的词库。
  • 风格目录：硬编码 12 种，若要运营可配需改为服务端下发。
  • 网络层：裸 HttpURLConnection，建议换 OkHttp + kotlinx.serialization。
恢复方法：jadx 1.5.6 静态解析（debug 包的 10 个 dex）+ androguard 4.1.4 结构清点 + APK 内版本元数据交叉验证； 关键分支用 jadx -m fallback 字节码模式逐条核对。
重写验证：Kotlin 2.1.20 编译器 + 真实 android.jar（API 36）编译通过，JUnit 4 跑通 58 个测试。
